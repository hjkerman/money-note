# 수동 테스트 체크리스트

이 문서는 사용자가 웹 화면을 직접 누르면서 `money-note`의 주요 기능을 확인하기 위한 체크리스트다.

## 테스트 전 주의

- [ ] 삭제, 초기화, 월마감 테스트에는 구분하기 쉬운 테스트 항목만 사용한다.
- [ ] API 서버가 실행 중이며 `http://127.0.0.1:18080/health`가 정상이다.
- [ ] 웹 앱 `http://127.0.0.1:5173`을 열었다.

## 로그인

- [ ] 로그인 전에는 가계부 조작 화면이 보이지 않는다.
- [ ] 잘못된 비밀번호를 입력하면 raw JSON 대신 `아이디 또는 비밀번호가 맞지 않습니다.`가 보인다.
- [ ] 올바른 계정으로 로그인하면 요약과 큰 탭들이 보인다.
- [ ] 새로고침 후에도 로그인 상태가 유지된다.
- [ ] 로그아웃하면 로그인 화면으로 돌아간다.
- [ ] 웹 로그인 응답 JSON의 `session_token`은 `null`이고 브라우저에는 HttpOnly cookie가 저장된다.
- [ ] 모바일 로그인만 장기 Bearer 토큰을 발급한다.
- [ ] 비밀번호 변경 후 기존 웹과 모바일 세션이 모두 다시 로그인을 요구한다.
- [ ] 로그인 실패를 기본 제한 이상 반복하면 잠시 `429`로 차단된다.

## 당월 지출

- [ ] `당월 > 당월 지출`에서 날짜, 사용처, 사용항목, 금액을 입력해 추가할 수 있다.
- [ ] 항목을 추가하면 날짜가 아닌 첫 입력 칸으로 포커스가 돌아간다.
- [ ] 추가한 적요가 `[사용처] 사용항목` 형태로 보인다.
- [ ] 추가 후 요약의 카드대금이 갱신된다.
- [ ] 지출 행을 삭제할 수 있다.
- [ ] 분류를 변경하면 즉시 서버에 저장되고 새로고침해도 값이 유지된다.
- [ ] 본인회원 카드의 월별 할인 혜택을 `혜택 있음`, `혜택 없음`으로 설정할 수 있다.
- [ ] 본인회원 카드는 기본값이 `혜택 있음`이고, 가족카드는 기본값이 `혜택 없음`이다.
- [ ] 혜택 있음인 달에는 카드 지출에 기본 1.2% 할인이 보인다.
- [ ] `할인 제외`를 누르면 해당 항목 할인액은 0원으로 계산된다.
- [ ] 제외한 항목에서 `할인 적용`을 누르면 기본 1.2% 할인 계산으로 돌아간다.
- [ ] 본인회원 카드 혜택을 `혜택 없음`으로 설정하면 할인액은 전부 0원으로 계산된다.
- [ ] 할인 미확인 여부 때문에 붉은 배경이 표시되지 않는다.
- [ ] 같은 원장 행의 할인 가능 여부, 할인액, 실결제액, 교통·통행 배지가 웹과 모바일에서 일치한다.
- [ ] 월 할인 정책을 바꾸면 웹과 모바일이 새 조회 결과를 받아 같은 값으로 갱신된다.
- [ ] 웹과 모바일 설정에서 교통카드 `본인카드와 동일`을 켜고 끌 수 있으며 변경 즉시 서버 결과로 갱신된다.
- [ ] 교통카드 설정이 꺼진 월에는 자동 할인액이 0원이다.
- [ ] 교통카드 설정이 켜진 월에는 본인카드 1.2% 계산식과 본인카드의 해당 월 혜택 있음/없음을 함께 따른다.
- [ ] 교통카드 프로필을 현재 월부터 바꿔도 이전 월 거래의 할인액은 그대로다.
- [ ] 통행료카드는 교통카드 설정과 무관하게 자동 할인액 0원을 유지한다.
- [ ] 수동 실결제액 보정은 교통카드 프로필보다 우선한다.

## 청구와 가족카드

- [ ] 청구와 가족카드 각각 항목을 추가할 수 있다.
- [ ] 테이블과 입력창이 하나의 panel 안에 붙어 있다.
- [ ] 각 행을 개별 삭제할 수 있다.
- [ ] `초기화`는 현재 탭의 항목만 삭제한다.
- [ ] 청구에는 자동 분류 결과가 표시되지 않는다.
- [ ] 가족카드 사용액과 본인 카드 사용액을 합산한 카드 한도 감시 문구가 표시된다.
- [ ] 청구는 본인회원 카드 할인 혜택 설정을, 가족카드는 별도의 가족카드 할인 혜택 설정을 보여준다.
- [ ] 같은 달에도 본인회원 카드와 가족카드의 할인 혜택 여부를 서로 다르게 설정할 수 있다.
- [ ] 청구와 가족카드 항목은 원래 금액과 할인 후 실제 금액을 함께 확인할 수 있다.
- [ ] 청구와 가족카드 탭 하단의 `공유하기` 버튼을 누르면 공유 링크가 복사된다.
- [ ] 청구 통계와 합계는 원래 금액보다 실 결제액을 우선한다.
- [ ] 청구 금액은 잔여 유동성 계산에 반영되지 않는다.
- [ ] 청구 공유 페이지에도 할인액과 할인 후 실제 청구 합계가 보인다.
- [ ] 청구와 가족카드는 사용일을 입력할 수 있고 사용일순으로 정렬된다.
- [ ] 공유 페이지 최소 결제 안내에 가장 이른 미정산 결제 연월이 표시된다.
- [ ] 가장 이른 회차 항목을 모두 처리하면 최소 결제 대상과 합계가 다음 회차로 자동 이동한다.

## 고정지출과 카드 정기결제

- [ ] 큰 탭 이름은 `고정지출`이다.
- [ ] 내부에 `현금성 고정지출`과 `카드 정기결제`가 함께 보인다.
- [ ] 현금성 고정지출을 추가하고 삭제할 수 있다.
- [ ] 현금성 고정지출 실제 출금액 input은 template 예정액으로 prefill되고, 수정하지 않으면 같은 금액의 음수 현금흐름이 생성된다.
- [ ] 예정 150,000원·실제 112,430원 확인 시 template은 150,000원으로 남고 잔여 유동성은 37,570원 증가한다.
- [ ] 예정 150,000원·실제 162,000원 확인 시 template은 150,000원으로 남고 잔여 유동성은 12,000원 감소한다.
- [ ] 실제 0원 확인은 이번 주기 미발생을 명시적으로 확정하고 reserve 전액을 잔여 유동성으로 되돌린다.
- [ ] 현금성 고정지출은 과거일과 당일에는 확인할 수 있지만 서버 기준 미래일은 거부된다.
- [ ] 실제액이 예정액과 같을 때 확인 전 미지급 고정지출 차감과 확인 후 현금흐름 차감이 겹치지 않아 잔여 유동성이 확인 전후 동일하다.
- [ ] 확인해도 현금성 고정지출 표시 총액은 줄지 않고 처리된 목록에 즉시 나타난다.
- [ ] 확인 직후 생성된 현금흐름을 삭제하면 월마감 전 템플릿이 미확인 상태로 돌아온다.
- [ ] 월마감 후 현금흐름은 남고 템플릿만 다음 주기 미확인 상태로 돌아온다.
- [ ] 카드 정기결제에 결제일, 사용처, 사용항목, 금액을 입력할 수 있다.
- [ ] 카드 정기결제 목록에서도 사용처와 사용항목이 서로 다른 열로 보인다.
- [ ] 카드 정기결제는 결제일순으로 표시되고, 사용항목이 비어 있으면 화면에 `좌동`으로 보인다.
- [ ] 카드 정기결제에서 사용항목만 비워둘 수 있고, 결제일·사용처·금액이 없으면 추가되지 않는다.
- [ ] 카드 정기결제도 카드 지출로 편입되면 같은 할인 정책을 따른다.
- [ ] 카드 정기결제의 `확인`을 누르면 같은 구조의 당월 지출이 만들어진다.
- [ ] 카드 정기결제 실제 원금 input은 template 예정 원금으로 prefill된다.
- [ ] 실제 원금을 늘리거나 줄이면 서버 preview의 기존 카드 할인 정책·반올림 결과와 확인 후 원장 할인/실결제액이 일치한다.
- [ ] 실제 원금을 다르게 확인해도 planned template 예정 원금은 바뀌지 않는다.
- [ ] `이번 승인 날짜`를 바꿔 확인하면 원장 지출의 `entry_date`만 그 날짜를 사용하고 정기결제 원본의 `due_day`는 유지된다.
- [ ] 확인 직후 활성 목록에서 빠지고 `이번 달 확인 처리된 정기결제` 목록에 실제 승인일과 함께 나타난다.
- [ ] 웹 확인 처리 목록은 이번 원금·할인·실결제액만 간결하게 표시하고, 모바일은 template 예정 원금과 이번 실제 원금을 구분해 보여준다.
- [ ] 제목과 금액이 같은 수동 지출이 있어도 확인 목록의 승인일은 `source_planned_entry_id`로 연결된 생성 지출에서 가져온다.
- [ ] planned 템플릿을 삭제해도 이미 생성된 원장 지출은 남고 원본 참조만 `NULL`이 된다.
- [ ] 카드 정기결제를 `확인`해도 카드 정기결제 패널의 총계는 줄어들지 않는다.
- [ ] 카드 정기결제를 `확인`해도 고정지출 탭의 총합계는 줄어들지 않는다.
- [ ] 카드 정기결제를 `확인`하면 잔여 유동성에서는 고정지출 예정액이 아니라 카드대금으로 한 번만 반영된다.
- [ ] 카드 정기결제 항목을 삭제할 수 있다.
- [ ] 월마감 전 생성된 정기결제 원장 expense를 삭제하면 template이 미확인 상태로 돌아와 실제 원금을 다시 확정할 수 있다.

## 동결

- [ ] 동결 항목을 추가하고 삭제할 수 있다.
- [ ] 동결 항목에는 당월 지출 자동 편입 버튼이 없고 개별 삭제만 가능하다.
- [ ] 웹에서 추가한 동결 항목은 서버 기준 등록일이 저장되고 웹·모바일에 같은 날짜로 표시된다.
- [ ] 월이 바뀌어도 미삭제 동결 항목은 웹·모바일 목록과 동결자산 총액에 계속 반영된다.
- [ ] 동결 금액은 소비 합계에 들어가지 않고 가용 유동성 평가에만 반영된다.

## 현금흐름과 이달 기준 수입

- [ ] 입금과 출금을 각각 추가할 수 있다.
- [ ] 출금은 음수, 입금은 양수로 표시된다.
- [ ] 현금흐름 추가 후 현금흐름 반영액과 잔여 유동성이 갱신된다.
- [ ] 입금 항목만 `이달 기준 수입`으로 표시할 수 있다.
- [ ] 이달 기준 수입 항목에는 `이달 기준 수입` 배지가 나타난다.
- [ ] 현금흐름 행을 삭제할 수 있다.
- [ ] 월마감 성공 시 닫힌 달의 다음 달 1일자로 설정 금액과 같은 `급여` 입금이 한 건 생성되고 `이달 기준 수입`으로 표시된다.
- [ ] 기본 예정 수입을 바꾼 뒤 다음 월마감을 하면 새 금액만 새 급여 행에 적용되고 이전 급여는 바뀌지 않는다.
- [ ] 조기 월마감으로 생성된 미래 날짜 `급여`는 행과 Snapshot에는 존재하지만 발생일 전 `cash_flow_balance`와 `remaining_liquidity`에는 들어가지 않는다.
- [ ] 급여 발생일이 되면 같은 행이 별도 상태 변경 없이 `cash_flow_balance`와 `remaining_liquidity`에 반영된다.

## 모바일 알림 수집

- [ ] 우리카드 승인 알림은 기존처럼 본인카드 또는 가족카드 후보로 생성된다.
- [ ] 우리카드가 아닌 일반 앱 알림은 저장되지 않는다.
- [ ] 고속도로 통행료+ `com.ex.hipass_app` 알림은 통행료 원문 로그와 로컬 후보로 저장된다.
- [ ] 통행료 후보는 날짜, 사용처 `통행료`, 확인된 구간, 금액을 자동 채운다.
- [ ] 요금 확인 불가 또는 금액 누락 알림은 빈 금액의 `partial` 후보로 남고, `알림 파싱 확인 필요` 알림을 표시하며, 등록 전 금액 입력을 요구한다.
- [ ] 날짜·시각이 없는 관련 통행료 알림은 후보를 만들지 않고 `failed` 로그와 확인 알림을 남긴다.
- [ ] 빈 Android 집계 알림과 지원하지 않는 알림은 로그와 후보를 만들지 않는다.
- [ ] 통행료 후보를 열어보기만 해서는 원장, 청구, 가족카드 API가 호출되지 않는다.
- [ ] 통행료 후보를 본인 사용 또는 청구 사용으로 등록할 수 있고 할인은 적용되지 않는다.
- [ ] 정상 통행료 후보는 별도 성공 알림을 만들지 않고 `새 내역 발견!`의 본인카드 미확인 건수에 합산된다.
- [ ] 후보 등록 또는 삭제 후 `새 내역 발견!`의 본인카드 미확인 건수가 즉시 갱신된다.
- [ ] 우리카드 파싱 실패·할부 수동처리와 통행료 파싱 실패·금액 미확인은 `알림 파싱 확인 필요`로 안내된다.
- [ ] `설정 -> 최근 납치한 알림`에 `우리카드`와 `통행료` 탭이 보이며 좌우 스와이프로 전환된다.
- [ ] 각 탭에서 packageName, title, text, bigText, rawText와 파싱 상태를 확인할 수 있다.
- [ ] 지원 목록에서 제거된 알림 출처의 기존 로컬 원문 파일은 앱 실행 시 삭제된다.
- [ ] 원문 로그를 항목별로 공유하고 삭제할 수 있다.
- [ ] 출처별 `로그 공유`와 `전체 삭제`가 다른 출처 로그를 건드리지 않는다.
- [ ] 각 출처 로그는 30건을 넘으면 가장 오래된 항목부터 제거된다.
- [ ] 통행료 후보가 있으면 `통행료 후보(계: n원)`이 보이고 금액 미확인 후보는 합계에서 제외된다.
- [ ] 기존 통행료 원문 로그는 앱 갱신 후 후보로 소급 생성되지 않는다.
- [ ] 알림 리스너를 재연결하면 알림창에 남은 지원 알림이 회수된다.
- [ ] 재연결로 같은 활성 알림을 다시 읽어도 후보와 원문이 중복되지 않는다.
- [ ] 등록·삭제한 후보는 같은 활성 알림을 재수집해도 7일 안에 되살아나지 않는다.
- [ ] 처리 이력은 마지막 관측 후 7일 또는 512건 제한을 넘으면 오래된 것부터 제거된다.
- [ ] 앱이 포그라운드일 때 후보 알림을 누르면 즉시 `알림에서 가져오기` 화면이 열린다.

## 이번달 결제

- [ ] 월마감 전에는 결제 작업함이 비어 있고 월마감 직후 활성 batch가 생성된다.
- [ ] 화면의 `usage_month`와 대상 행이 마지막 월마감 batch 기준으로 표시된다.
- [ ] batch 사용내역이 날짜 오름차순으로 표시된다.
- [ ] `사용 일자` 열의 날짜가 좁은 화면에서도 잘리지 않는다.
- [ ] 적요에 `교통` 문자열이 있는 항목에는 교통 배지가 나타난다.
- [ ] 모든 카드 사용내역에 `이월` 버튼이 나타난다.
- [ ] 하이패스/통행료 항목이 여러 건이면 결제 대상 목록에서 하나의 통합 행으로 보인다.
- [ ] 통행료/하이패스 항목도 일부 즉시결제할 수 있다.
- [ ] 통합 행에 일부 금액을 입력하면 원본 하이패스/통행료 항목에 순서대로 배분된다.
- [ ] 날짜순 자동 배분은 교통·통행료 항목을 선택하거나 배분하지 않는다.
- [ ] 카드 사용내역의 `이월`을 누르면 현재 결제 합계와 자동 배분 대상에서 제외된다.
- [ ] 이월한 항목은 당월 사용내역 맨 앞에 날짜 없이 `[이월]` 적요로 나타난다.
- [ ] 같은 결제월에 `이번 달에 처리`를 누르면 원래 장부 날짜, 적요, 위치가 복원된다.
- [ ] 14일까지는 이월과 `이번 달에 처리` 전환이 가능하다.
- [ ] 15일부터는 이월이 확정되어 `이번 달에 처리`로 되돌릴 수 없다.
- [ ] 다음 결제월에는 이월 항목이 날짜 없이 `[이월]` 적요로 결제 대상 맨 앞에 나타난다.
- [ ] 다음 결제월의 이월 항목에는 재이월 버튼이 나타나지 않는다.
- [ ] `전월 매입 지연 보정`에서 직전월 날짜, 사용처, 사용항목, 금액을 입력해 추가할 수 있다.
- [ ] 전월 보정으로 추가한 항목은 즉시 이번달 결제 대상에 나타난다.
- [ ] 직전월이 아닌 날짜는 전월 보정에 추가할 수 없다.
- [ ] 결제 대상 목록에서 사용내역을 삭제할 수 있다.
- [ ] 통합 행을 삭제하면 그 안의 원본 하이패스/통행료 항목이 함께 삭제된다.
- [ ] 결제 대상 목록에서 삭제한 항목은 월별 기록의 원장에서도 사라진다.
- [ ] 집에 청구하는 하이패스/통행료 항목은 청구 탭에서 개별 항목으로 유지된다.
- [ ] 카드사 환급은 과거 기록을 삭제하지 않고 현금흐름 입금으로 기록한다.
- [ ] 각 항목의 원래 금액, 즉시결제 누적, 할인 누적, 남은 금액이 보인다.
- [ ] 원래 사용금액은 결제 처리 후에도 변하지 않는다.
- [ ] 원하는 항목을 직접 선택하거나 선택 해제할 수 있다.
- [ ] 선택 항목의 이번 처리액을 남은 금액보다 작은 일부 금액으로 직접 입력할 수 있다.
- [ ] 자동 배분 한도를 입력하고 `날짜순 자동 배분`을 누르면 앞 항목부터 배분된다.
- [ ] 마지막 선택 항목은 한도에 맞춰 일부 금액만 배분된다.
- [ ] 자동 배분 한도를 비우면 현금흐름 반영액이 기본 한도로 사용된다.
- [ ] 즉시결제 반영 후 같은 금액의 현금흐름 출금이 생성된다.
- [ ] 같은 idempotency key와 같은 즉시결제 payload를 재전송해도 결제 이벤트와 현금흐름은 각각 한 건만 생긴다.
- [ ] 같은 idempotency key에 다른 payload를 보내면 거부된다.
- [ ] 서로 다른 key의 동시 요청이 같은 남은 결제액을 초과하여 성공하지 않는다.
- [ ] 즉시결제 기록을 취소하면 연결된 현금흐름도 함께 삭제된다.
- [ ] 할인액은 남은 결제금액만 줄이고 현금흐름을 만들지 않는다.
- [ ] 이번 달에 이달 기준 수입이 있으면 심사 기준 수입으로 사용된다.
- [ ] 이달 기준 수입이 없으면 기본 예정 수입이 사용된다.
- [ ] 설정 화면에서 기본 예정 수입을 변경할 수 있다.
- [ ] 남은 결제액과 14일까지 남은 날짜에 따라 파산심사위원회 문구가 달라진다.
- [ ] 같은 결제 상태에서 새로고침해도 파산심사위원회 문구가 임의로 바뀌지 않는다.
- [ ] 같은 위험 등급에서도 결제일까지 남은 날짜 또는 미결제액을 바꾸면 다른 문구가 나타날 수 있다.

## 결제일 경과 처리

날짜 변경이 필요한 항목이므로 별도 테스트 DB 또는 개발 환경에서 확인한다.

- [ ] 익월 14일에는 즉시결제가 가능하다.
- [ ] 익월 15일부터는 즉시결제가 차단된다.
- [ ] 15일 이후에도 기록상 미결제액은 화면에 남아 사용자가 직접 확인할 수 있다.
- [ ] `결제 안 된 내역 있습니다. 현금흐름 반영액을 재설정하세요.` 안내가 나타난다.
- [ ] 실제 현금흐름 반영액을 수동 보정한 뒤 `현금흐름 보정 완료`를 누르면 안내가 사라진다.

## 가족 공유 PIN과 카카오톡

- [ ] 새 DB에서 청구/가족카드 공유 링크를 열면 기본 PIN `0000` 입력 화면이 나타난다.
- [ ] 기본 PIN `0000`을 입력하면 공유 페이지에 정상 접근할 수 있다.
- [ ] 기본 PIN 상태에서 본체에 로그인하면 PIN 변경 경고 문구와 `지금 PIN 변경` 버튼이 나타난다.
- [ ] 기본 PIN `0000`을 다시 설정해도 변경 경고가 유지된다.
- [ ] 본체 웹 상단의 `공유 PIN 설정`에서 숫자 네 자리를 설정할 수 있다.
- [ ] 기본값이 아닌 PIN 설정 후 본체의 PIN 변경 경고가 사라진다.
- [ ] PIN 설정 후 공유 링크를 새 브라우저에서 열면 PIN 입력 화면이 나타난다.
- [ ] 잘못된 PIN은 거부된다.
- [ ] 올바른 PIN 입력 후 공유 내용이 열린다.
- [ ] 카카오톡 인앱 브라우저에서도 PIN 입력과 공유 화면 열기가 정상이다.
- [ ] 카카오톡에서 링크를 다시 열었을 때 사이트 데이터가 유지되어 있다면 PIN을 다시 요구하지 않는다.
- [ ] 본체 웹에서 PIN을 변경하면 기존 공유 세션은 다시 PIN을 요구한다.
- [ ] 공유 화면에는 계좌번호, 송금 링크, 개인정보가 보이지 않는다.

## 통계와 월별 기록

- [ ] 요약 상단에 예산심사위원회 한 줄 평이 표시된다.
- [ ] 당월 지출, 현금흐름, 청구, 가족카드, 동결에 테스트 항목을 하나씩 추가할 때마다 상단 한 줄 평이 달라진다.
- [ ] 장부를 바꾸지 않고 새로고침하면 상단 한 줄 평이 유지된다.
- [ ] `통계 보기`를 누르면 소비 통계와 월별 기록이 함께 나타난다.
- [ ] 모달 상단의 공용 연-월 선택을 바꾸면 카드 소비 통계와 월별 기록이 같은 월 기준으로 다시 표시된다.
- [ ] 모달에서 `카드 지출`과 `현금흐름`을 전환해도 선택한 연-월이 유지된다.
- [ ] 웹 현금흐름 탭에는 직전 월부터 당월까지의 기록만 보이고, 전체 과거 기록은 통계 모달의 현금흐름 보기에서 월별로 조회된다.
- [ ] 현금흐름 월별 기록은 일자, 내용, 금액만 표시하며 입금은 초록색 `+`, 출금은 빨간색 `-` 금액으로 구분된다.
- [ ] 선택한 월의 구조화된 current/archive 기록과 합계가 보인다.
- [ ] `/api/judgment/current`의 budget 현금흐름 입력에는 서버 기준 당월 행만 들어가고, 과거 현금흐름은 Summary 누계에만 남는다.
- [ ] 웹 월별 기록은 오래된 날짜가 위에 오고, 같은 날짜에서는 먼저 등록한 항목이 위에 온다.
- [ ] 모바일 본인 원장은 최신 날짜가 위에 오고, 같은 날짜에서는 나중에 등록한 항목이 위에 온다.
- [ ] 당월 지출 표에서는 사용처, 사용항목, 분류가 서로 다른 열로 보인다.
- [ ] 월별 기록 표는 조회 전용이며 분류 드롭다운과 삭제 버튼이 보이지 않는다.
- [ ] 당월 지출에서 사용항목만 비워둘 수 있고, 날짜·사용처·금액이 없으면 추가되지 않는다.
- [ ] 금액 입력칸에는 일반 텍스트를 입력할 수 없고 정수 숫자만 허용된다.
- [ ] 현금흐름을 제외한 금액 입력/API에 음수를 넣으면 거부된다.
- [ ] 존재하지 않는 달력 날짜는 API에서 `422`로 거부된다.
- [ ] generic 원장·패널 PATCH로 확인 상태, 패널 타입, 할인 상태 같은 state-machine 필드를 바꾸려 하면 `422`로 거부된다.
- [ ] 항목 추가 성공 후 날짜 칸은 건너뛰고 해당 폼의 첫 입력칸으로 focus가 돌아간다.
- [ ] 통계와 판단 문구 외의 기본 조작 UI에는 불필요한 유머 문구가 없다.
- [ ] 청구 공유 문구가 의료, 치과, 교통, 소액 다건 같은 청구 구성에 따라 달라진다.
- [ ] 의료 청구 2건 이하는 정기 유지보수인 안 아픈 달로 평가된다.
- [ ] 의료 청구 3건은 정기 진료 외에 한 번 아팠던 달로 평가된다.
- [ ] 의료 청구 4건 이상은 집에서 걱정할 만큼 많이 아픈 달로 평가된다.
- [ ] 가족카드 공유 문구가 합산 한도 사용률과 특정 고액 항목 집중도에 따라 달라진다.

## 모바일 ChatGPT 회계감사

- [ ] 홈의 예산심사위원회 카드 문구와 모양은 기존과 같고, 카드를 누르면 `ChatGPT에게 회계감사 받기` 창이 열린다.
- [ ] 연월 선택기는 데이터가 있는 연월만 표시하며 미래와 데이터가 없는 연월은 표시하지 않는다.
- [ ] 서버 현재 월에 데이터가 있으면 그 달이 기본 선택되고, 없으면 데이터가 있는 가장 최근 월이 선택된다.
- [ ] `회계감사 소집` 직전에 데이터를 다시 조회하고 선택 월의 본인 카드 지출, 현금흐름, 미정산 청구와 가족카드를 Markdown 한 파일로 만든다.
- [ ] 본인 카드 지출의 할인액과 실결제액은 서버 API 응답과 일치하며 모바일에서 다시 계산한 값이 아니다.
- [ ] Markdown 표 안의 `|`, 줄바꿈, 역슬래시가 표 구조를 깨뜨리지 않는다.
- [ ] ChatGPT Android 앱에는 `.md` 파일만 첨부되며 별도의 고정 문구는 입력되지 않는다.
- [ ] 역할, 데이터 해석 규칙과 결과 작성 순서는 모두 `.md` 안에 있고 사용자는 전송 전 추가 질문을 작성할 수 있다.
- [ ] ChatGPT 앱이 없으면 설치 필요 안내가 보이고 Money-Note가 종료되지 않는다.
- [ ] ChatGPT에서 Money-Note로 돌아온 뒤 앱 cache의 회계감사 임시 파일이 삭제된다.
- [ ] 공유 중 Money-Note가 종료된 경우 다음 실행 시 남은 회계감사 임시 파일이 삭제된다.
- [ ] 보고서의 청구와 가족카드는 처리 완료 후 삭제되는 운영 데이터이므로 현재 남은 미정산 항목만 포함된다고 명시된다.
- [ ] 보고서의 현재 운영 참고자료에 현금성 고정지출과 확인 여부와 무관한 카드 정기결제 템플릿이 모두 표시된다.
- [ ] 현재 남아 있는 동결 항목은 등록일·내용·금액으로 표시되고, 삭제된 과거 동결 이력을 제공하는 것처럼 표현하지 않는다.
- [ ] 고정지출·정기결제·동결 자료가 선택 월 당시의 이력이 아니라 보고서 생성 시점 현재 상태라고 명시된다.

## 설정과 백업

- [ ] 설정 모달에서 기본 예정 수입, 현금흐름 반영액, 카드 한도를 수정할 수 있다.
- [ ] 독립된 고정 비용 설정은 없으며 반복 현금 지출은 현금성 고정지출로 등록하고 확인 처리한다.
- [ ] Summary와 설정 API는 `scheduled_income`, `cash_flow_balance`, `remaining_liquidity`만 반환하고 과거 alias는 반환하지 않는다.
- [ ] 웹과 모바일은 `scheduled_income`, `cash_flow_balance`, `remaining_liquidity`만 읽는다.
- [ ] 과거 기본 라벨만 새 용어로 정규화되고 사용자 지정 라벨은 보존된다.
- [ ] 설정 모달에서 비밀번호를 변경할 수 있고, 변경 후 새 비밀번호로 다시 로그인할 수 있다.
- [ ] `snapshot 백업 다운로드`를 누르면 `.money-note-snapshot.json` 파일 하나가 내려받아진다.
- [ ] 새 snapshot의 `schema_version`은 7이고 `card_charge_policy`, `card_charge_policy_sha256`, `content_sha256`이 포함된다.
- [ ] v7은 `monthly_panels.confirmed_month`, `ledger_entries.source_planned_entry_id`, 카드 결제 idempotency 필드를 보존한다.
- [ ] v4~v6에 v7 nullable 필드가 없어도 `NULL`로 복원된다.
- [ ] snapshot 생성 도중 다른 write가 commit되어도 여러 테이블에 서로 다른 시점이 섞이지 않는다.
- [ ] snapshot 복원은 현재 비밀번호 없이는 실행되지 않는다.
- [ ] 잘못된 snapshot 파일을 올리면 복원이 차단되고 기존 화면이 계속 조회된다.
- [ ] 정책 명세가 변조되거나 현재 서버 정책과 다른 지원 버전 snapshot은 복원이 차단되고 기존 DB가 유지된다.
- [ ] 파일 형식 버전 3 이하 snapshot은 지원하지 않는 버전으로 차단되고 기존 DB가 유지된다.
- [ ] 버전 4 snapshot은 원문 manifest 검증 후 유동성 key가 현재 이름으로 이동하고 교통카드 프로필 설정 이력이 복원된다.
- [ ] 같은 의미의 과거/현재 유동성 key 값이 충돌하는 DB 또는 snapshot은 migration을 중단한다.
- [ ] 지원 snapshot export/restore 전후 주요 row count와 예정 수입·현금흐름 반영액·잔여 유동성·카드대금이 같다.
- [ ] 복원 직전 백업 목록에서 항목을 조회할 수 있다.
- [ ] 복원 직전 백업의 개별 삭제와 일괄 삭제가 동작한다.
- [ ] 복원 직전 백업 되돌리기는 현재 비밀번호 없이는 실행되지 않는다.
- [ ] 설정 모달 하단에서 DB 파일 크기, 추정 운영 데이터 크기, pre_restore 합계, 테이블별 row count를 볼 수 있다.
- [ ] Android APK 파일이 서버에 있으면 `APK 다운로드` 버튼으로 APK가 내려받아진다.
- [ ] Android APK 파일이 없으면 다운로드 실패 메시지가 보이고 장부 데이터는 변하지 않는다.
- [ ] 모바일 설정 탭 맨 아래의 `APK 다운로드`는 버전 비교 없이 서버의 현재 APK를 인증 상태로 받는다.
- [ ] 최초 설치 권한이 없으면 Android의 `이 출처의 앱 설치 허용` 화면이 열리고, 허용 후 버튼을 다시 누르면 다운로드가 시작된다.
- [ ] APK 다운로드 중에는 진행률이 표시되고 버튼을 중복으로 누를 수 없다.
- [ ] 다운로드가 중단되거나 파일 크기가 응답과 다르면 설치 화면이 열리지 않고 `.part` 파일이 삭제된다.
- [ ] Money-Note와 package name이 다른 APK는 설치 화면을 열기 전에 거부된다.
- [ ] Money-Note와 서명 인증서가 다른 APK는 설치 화면을 열기 전에 거부된다.
- [ ] 정상 APK는 Android 업데이트 설치 화면을 열고, 설치 취소 또는 완료 후 앱 cache의 임시 APK가 삭제된다.
- [ ] 기본 `1 MiB` 제한을 넘는 일반 변경 API 요청은 `413`으로 거부되고 장부 데이터는 변하지 않는다.
- [ ] 25 MiB 제한을 넘는 snapshot restore 요청은 `413`으로 거부되고 현재 DB는 유지된다.

## 초기화와 월마감

- [ ] 설정 모달의 장부 데이터 전체 초기화는 현재 비밀번호 없이는 실행되지 않는다.
- [ ] 장부 데이터 전체 초기화 직전에 복원 전 백업이 하나 생성된다.
- [ ] 초기화 후 계정, 로그인 세션, 공유 PIN, 기본 예정 수입 설정은 유지된다.
- [ ] 테스트 데이터만 있는 상태에서 월마감을 실행한다.
- [ ] 월마감 직전에 복원 전 백업이 하나 생성된다.
- [ ] 상태 API에서 확인한 `oldest_open_month`를 `target_month`로 보내 월마감한다.
- [ ] 미확인 현금성 고정지출과 카드 정기결제가 있으면 상태 응답 한 목록에 모두 나타난다.
- [ ] 미확인 정기지출이 있는 기본 월마감 요청은 장부 변경과 pre_restore 생성 전에 거부된다.
- [ ] Web과 Mobile에서 항목 목록을 확인한 뒤 `그래도 월마감`을 선택하면 explicit override로 정상 마감된다.
- [ ] 정기지출을 모두 확인한 대상 월은 추가 경고 없이 정상 마감된다.
- [ ] 같은 `target_month`를 순차 또는 동시에 재요청해도 archive, 급여와 결제 batch가 한 번만 생성된다.
- [ ] 월마감 도중 결제 batch 생성이 실패하면 원장 이동과 자동 `급여` 입금이 모두 rollback된다.
- [ ] 새 달인데 이전 월 장부가 남아 있으면 첫 화면에 월마감 검토 경고가 나타난다.
- [ ] 26일까지는 현재 달 조기 월마감 버튼이 비활성화된다.
- [ ] 27일부터 현재 달 조기 월마감 확인창과 버튼이 활성화된다.
- [ ] 조기 월마감 후 같은 달 날짜로 지출을 추가하면 전체 기록에 추가되었다는 안내가 나타난다.
- [ ] 이전 월 말일 기록과 새 달 1일 기록을 모두 추가한 뒤 월마감한다.
- [ ] 가장 오래된 이전 월 일반 지출만 전체 기록으로 이동한다.
- [ ] 먼저 추가한 새 달 기록은 당월 기록에 그대로 남는다.
- [ ] 현재 달만 남은 상태에서는 월마감 버튼이 비활성화된다.
- [ ] 밀린 과거 월마감 전에 이후 주기의 현금성 고정지출을 확인해도 그 확인 상태와 현금흐름이 유지된다.
- [ ] 카드 정기결제는 다음 달에도 남는다.
- [ ] 새 월마감이 기존 활성 batch를 교체하면 이전 batch의 임시 결제 배분은 남지 않는다.
- [ ] 청구 `일괄 처리 완료`는 저장 월과 무관하게 현재 남은 청구 큐 전체만 목록과 공유 페이지에서 삭제한다.
- [ ] 청구 `일괄 처리 완료` 직전에 복원 전 백업이 하나 생성된다.
- [ ] 가족카드 `일괄 처리 완료`는 저장 월과 무관하게 현재 남은 가족카드 큐 전체만 목록과 공유 페이지에서 삭제한다.
- [ ] 가족카드 `일괄 처리 완료` 직전에 복원 전 백업이 하나 생성된다.
- [ ] 청구 본인용 표에는 자동 분류 열이 없고 공유 판단 문구는 정상적으로 나타난다.

## 관리 로그

- [ ] 항목 추가·수정·삭제 후 `관리 로그`에 HTTP 방식, 경로, 결과 코드가 나타난다.
- [ ] 관리 로그에는 요청 본문, 비밀번호, 세션 토큰이 보이지 않는다.
- [ ] `로그 초기화` 확인창에서 취소하면 로그가 유지된다.
- [ ] `로그 초기화`를 승인하면 전체 로그가 사라지고 초기화 요청 자체는 새 로그로 남지 않는다.
